Part 1 · CS1.K1

Designing functions

Write the steps once. Use them as often as you need.

Section opener. Remind students of Science 7: they used built-in functions like move and print. Now they design their own. Ask: where in your life do you follow the same set of steps many times? A morning routine, tying skates, a warm-up drill. Each could be a function with a name.

Science 8 · CS1 · Functions

Defining designs the function: a descriptive name, inputs (also called parameters) and the algorithm. Calling runs it. In block tools you usually make your own block with a define hat. Demo in the lab: Learn tab, Lesson 1. Switch the input to “no input” and run it: the function always flashes 2 times, so the second call cannot flash 3 times. Then try the names doIt and f1: the code still runs but nobody can tell what it does. Teacher note: “functions can be designed” is taught as defining your own function and then calling it.

Part 2 · CS1.K2 to K4

Events and sensors

How a program notices that something happened, and what it does next.

Section opener. Return to the hook question: how does the step counter know? Today’s answer has two parts: a sensor notices the movement, and an event starts the counting code.

CS1.K2 · Events

An event is something a program can detect

Action

Someone does something: presses a button or clicks a mouse.

Change

Something in the world changes: the light level drops as a cloud passes.

Occurrence

Something happens: a timer reaches 10 seconds or a message arrives.

The key word is detectable. A button, a sensor or the computer’s own clock must be able to notice it.

Science 8 · CS1 · Events and sensors

Ask: can the practice board detect that a student feels bored? No: it has no way to measure feelings, so that is not an event for this program. Can it detect a birthday? Not this board, but a phone could, because it stores the date and the birthday. Lab link: Learn tab, Lesson 2 (tap each happening).

CS1.K3 · Events

A program recognizes an event and responds. An event hat like when button A pressed starts the code under it.

Science 8 · CS1 · Events and sensors

Demo: Learn tab, Lesson 3. Press A five times: at 5 taps an internal event (when taps = 5) shows a smile and resets the count. Start the 10 second timer for a second internal event. Point out that between events the board just waits: code runs only when needed. Accuracy note for teachers: “a count is completed” is modelled in the lab with a “when condition” hat that fires once when the condition becomes true; some block tools do this with a timer hat or a broadcast message instead. Block names are generic, not tied to one product. Practice: Sort It tab, “External or internal event?”.

CS1.K4 · Sensors

Sensors bring the world into the IPO cycle

INPUT

Soil moisture sensor reads 22%.

PROCESS

Is 22 less than the set value, 30? Yes.

OUTPUT

Pump on: water the plants.

A sensor collects data from the environment: light, temperature, moisture, tilt or distance. Then the cycle repeats with the next reading.

Science 8 · CS1 · Events and sensors

Connect to Science 7: the IPO cycle. Sensors are the input stage. Ask: what is the difference between a button and a sensor? A button is an input device you press; a sensor measures something in the environment. The 22% reading and the set value of 30% are example numbers. Lab link: Learn tab, Lesson 4. Move the slider across 30 and watch the output box change.

CS1.K4 · CS1.S6 · Sensors

Sensors at work, from robots to greenhouses

Line-following robot

A light sensor points at the floor. A dark line reflects little light, so a low reading means “on the line”.

School greenhouse

A soil moisture sensor turns on a pump only when the soil is dry.

Block heater

An outdoor temperature sensor turns the heater on below a set value, for example −15 °C.

Hallway lights

A distance sensor turns the lights on when someone comes close.

Science 8 · CS1 · Events and sensors

Robotics is the application the curriculum names; the others are local examples. Ask students to add one more sensor they see around the school or at home. Lab link: Lab Bench, Investigation 6 (sensor explorer). Each application has 24 made-up readings; students move the set value and count how often the event fires. Key idea: an event “when the reading drops below” fires once per crossing, while an “if below” check at every reading responds every time. Accuracy flag for Lance: the block heater set value (about −15 °C) is a common Alberta rule of thumb used as an example; please check wording.

Science 8 · CS1 · Variables

Ask students to rename x for a variable that stores the outdoor temperature (tempOutside). Then the value types: add works on numbers, join sticks text together. Accuracy note for teachers: how text that looks like a number is handled varies. Some block tools turn “5” into 5 and give 10 when adding; Python gives an error for 5 + “5” and joins “5” + “5” into “55”. True or false (Boolean) values and lists exist too but are only mentioned in the lab’s flashcards. Lab link: Learn tab, Lesson 6; Sort It, “Number or string?”.

Lab link: Learn tab, Lesson 7. Choose each teammate and step through the code while watching the laps box. Function example: addLaps(2) then addLaps(3) gives laps = 5. Part 4 · CS1.K8

Efficient code

Putting functions, variables and events to work together.

Section opener. Ask: what makes one program better than another if both do the same job? Collect ideas such as shorter, faster, easier to fix, fewer mistakes. Keep the list for the debate slide.

CS1.K8 · The big idea

Efficient code does its job with fewer wasted steps. It is shorter, clearer and easier to fix, so it runs more reliably.

Read the statement together. Accuracy flag for Lance: the curriculum says efficient code ensures programs “run faster and more reliably”. The lab teaches this more precisely. Functions and variables mainly make code shorter, clearer and easier to change and fix, which makes it more reliable. Events let the program run code only when something happens instead of checking again and again in a forever loop; in block tools the system still watches for the event behind the scenes, so the saving is in the program’s own steps. Calling a function does not by itself make code run faster.

Science 8 · CS1 · Efficient code

Give students 30 seconds. Answer: the show block runs before the change block, so the board shows the old value. Fix: move show below change, then test again. Lab link: Lab Bench, Investigation 5 has nine bugs in random order: a wrong starting value, the wrong event, set instead of change, show before change, a loop that runs too few times, a misspelled variable (lifes), the wrong comparison, a function that ignores its input, and join instead of add. Connect to efficiency: with a function, you fix a bug once.

Three questions

A timer reaching 10 seconds: external or internal event?

2

lives is 3. The program runs change lives by −1 twice. What is lives now?

3

The winning score 5 is typed in three places. What is the more efficient fix?

Science 8 · CS1 · Review

Answers. 1: internal, because the timer is kept by the computer’s own clock. 2: lives is 1 (3 − 1 − 1). 3: store it once in a variable such as goalTarget, so changing it means changing one value. Use mini whiteboards or fingers for 1 and 2. For more practice: Quiz tab (10 questions from a bank of 26) and Flashcards.

Debate · Written Review

“Shorter code is always more efficient.” Do you agree?

Take a position

Agree, disagree, or “it depends”.

Use evidence

Compare lap counters B and C from the lab.

Name the measures

Blocks, steps while waiting, places to fix.

Science 8 · CS1 · Review

This is extended response 3 in the lab’s Written Review tab. Run it as a four corners debate, then have students write their answer in the lab and tick the key ideas. Model answer: not always. In the lab, the event and function version had a few more blocks than the loop version, but it was more efficient while waiting, because it did not check the sensor again and again, and it was easy to fix in one place. Efficient code uses functions, variables and events well; length is only one measure. Bring back the list of ideas from the Efficient code opener.

Programs and Instructions Lab

Understanding: Computers use programs to perform tasks. A program is a list of exact instructions. In this lab you will break big tasks into small ones, build code from blocks, look inside functions, follow data through the input–process–output cycle, and see how hardware, software and interfaces work together.

Learn

Eight short lessons in order. Each one has a model to try. Many models use a small robot called the turtle. It lives on a grid and does exactly what its code says, nothing more and nothing less.

Lesson 1 · What a program is
CS1.K1

A program is a list of exact instructions

A program is a set of instructions that a computer can run to do a task. The instructions are written in a programming language: a language with strict rules that a computer can follow.

People can handle a vague instruction like “go over there”. A computer cannot. It needs every step spelled out, in the right order, with the right words.

Some languages use visual blocks that snap together. Others use typed text, like Python. Either way, the computer translates the code into very simple machine instructions before its processor runs them.

Remember: a computer follows a program exactly. If the instructions are wrong, the computer does the wrong thing.

Model: run a program one instruction at a time

The turtle should reach the flag. Press Run one line to follow the program step by step. Then switch the language view.

Lesson 2 · Decomposition
CS1.K2

Break a big task into small parts

Decomposition means breaking a task into smaller parts. Each small part is easier to understand, write and test.

Take the task “draw a winter scene”. It splits into the sky, the ground, a spruce tree and a snowman. The snowman splits again into three snowballs and a face.

Each small part can become a function in the program, such as drawTree() or drawSnowman(). The main program then just calls the functions in order.

Remember: decompose until each part is small enough to write as one function.

Model: decomposition tree

Select a box to see what it does and which function could handle it.

Lesson 3 · Functions
CS1.K3CS1.K5

A function is a named block of code with one job

A function is an organized block of code that does one specific task. You write it once, give it a name, and then call it whenever you need that task done.

A function has four parts:

  • a descriptive name that says what it does, like drawSquare
  • inputs, the values you hand it, like the size of the square
  • an algorithm, the ordered steps inside it
  • an output, the result it gives back or the action it causes

Some functions need no inputs. turnRight() always turns the same way. Some functions do an action, like drawing, instead of handing back a value. Programmers call the inputs parameters.

Model: the function machine

Choose a function. Change its inputs and watch the algorithm and output change.

Lesson 4 · Built-in functions
CS1.K4

Languages come with ready-made functions

Most programming languages include built-in functions for common jobs. Someone already wrote and tested them, so you can just use them.

Four common ones are move, draw, print and add. Their exact names change from language to language. In Scratch, “draw” is done with pen blocks. In Python, adding often uses the + sign. The idea stays the same: a ready-made tool for a common task.

You can also write your own functions, like drawSnowman(), by putting built-in functions together.

Remember: built-in functions come with the language. Your own functions are built from them.

Lesson 5 · Sequences, loops and conditionals
CS1.K5

Functions can be used in three kinds of structure

A sequence runs instructions one after another, in order.

A loop repeats instructions. repeat 4 runs the blocks inside it four times.

A conditional makes a choice. If something is true, then do one thing, else do another.

The same function can sit inside any of these. In the model, move() and print() appear in all three.

Model: one function, three structures

Pick a structure and press Run. For the conditional, choose today’s weather first.

Lesson 6 · The IPO cycle
CS1.K6

Input, process, output

The input–process–output (IPO) cycle is a model of how a computer system works.

  • Input: data comes in through hardware such as a keyboard, a sensor or a scanner.
  • Process: software tells the processor what to do with the data.
  • Output: the result goes out through hardware such as a screen, a speaker or a motor.

It is a cycle because the output often leads to new input. A furnace warms the room, the sensor reads the new temperature, and the loop runs again. Many versions of the model also add storage, where data is saved for later.

Model: follow the data

Choose a system. Select each stage to see the hardware and software at work.

Lesson 7 · Hardware and software
CS1.K7CS1.K8

Software tells hardware what to do

Hardware is the physical parts of a computer: the parts you could touch. Software is code. It instructs the hardware.

There are three main types of software:

  • System software runs the computer itself. An operating system, such as Windows, macOS, ChromeOS, Android or iOS, lets people use the computer efficiently.
  • Programming software helps programmers write code. Examples are code editors and block coding tools.
  • Application software helps users do tasks, such as a word processor for writing or a spreadsheet for working with data.

Model: the computer stack

Select a layer. Each layer depends on the one below it.

Lesson 8 · Interfaces
CS1.K9

Interfaces let parts talk to each other

An interface is a device or program that lets two things communicate.

A user interface connects a person and a computer. A touch screen is one. So are a keyboard, a mouse and the buttons on a screen.

A driver is software that connects other software to hardware. A printer driver turns your document into commands that one model of printer understands.

Software settings can change an interface too. The same keyboard can type Canadian French accents, or Cree syllabics, once the right keyboard layout is turned on.

      Teacher notes

      • CS1.K1: the lab adds that code in a programming language is translated (compiled or interpreted) into machine instructions before the processor runs it. The “processor view” in Lesson 1 is an illustration, not real machine code.
      • CS1.K4: draw, add, print and move are taught as common built-in jobs whose names vary by language. In Scratch, drawing uses pen blocks and adding uses an operator block; in Python, adding usually uses the + operator and print() is a built-in function. The lab’s turtle uses the four names exactly as listed.
      • CS1.K5: the four parts of a function are taught, with the more precise note that some functions take no inputs (turnRight()) and some produce an action instead of returning a value (drawSquare()). Inputs are also called parameters.
      • CS1.K6: IPO is taught as a cycle in which output can lead to new input (feedback). Storage is mentioned once because many textbooks use an input–process–output–storage model.
      • CS1.K8: software categories are taught as helpful groups that can overlap. Operating system examples (Windows, macOS, ChromeOS, Android, iOS) are named as common examples, not endorsements.
      • CS1.K9: a driver is taught as software that lets the operating system and applications communicate with one model of hardware; a touch screen is taught as hardware that is part of a user interface. Keyboard layouts for Canadian French and Cree syllabics are mentioned once as examples of software settings that change an interface; please review this wording.
      • Data: the trace programs are randomized practice. The setups, systems and code review cases are made up for practice and labelled as such.

Blocks to Text Lab

Understanding: Text-based programming languages can enable computers to perform more complex tasks. In this lab you will put block code next to Python, JavaScript and Java, learn the rules each language follows, plan with pseudocode, and explain what short programs do.

Learn

Six short lessons in order. Each one has a model to try. The code samples use three popular text languages: Python, JavaScript and Java.

Lesson 1 · Blocks and text

Same program, two ways to write it

CS1.K1CS1.S1

In visual block-based programming, you build a program by snapping shapes together. Each block already has the right shape, so it only fits where it is allowed.

In text-based programming, you type the instructions. A text language uses words, phrases, numbers and keyboard symbols such as ( ) : ; { } = " to tell the computer what to do.

Blocks also contain words. The big difference is how the code is made: you choose and drag blocks, but you type text code one character at a time.

Try it: tap a block. The matching line of text code lights up. Switch languages to see that the same idea can be typed in different ways.

      Lesson 2 · More control
      
Why programmers move to text

      
CS1.K2

      
Block tools are great for learning because they hide many details. Text languages show those details, and that gives you greater control over how a program is designed.

      
With text you can choose exactly how numbers look, open data files, use huge collections of ready-made code called libraries, and organize data in many ways.

      
More control has a cost. You have to follow every rule yourself, so there are more ways to make mistakes.

      
Some block tools, such as Microsoft MakeCode, can switch a program between blocks and text. That makes them a good bridge.

      Lesson 3 · Syntax
      
Every language has its own rules

      
CS1.K3CS1.K4CS1.S4

      
Text languages have three key features: syntax, structure and complexity. This lesson is about syntax.

      
Syntax is the set of rules for how symbols, words and numbers can be arranged to make a program. It is like spelling and grammar for code. Each language has its own syntax.

      
If you break a syntax rule, you get a syntax error, and the program usually will not run at all. A computer cannot guess what you meant.

      
Try it: tap each piece of the line to learn its job. Then break the code on purpose and read the error.

      Lesson 4 · Structure
      
How code is organized

      
CS1.K3CS1.S1

      
Structure is the way code is organized: the order of the lines, which lines belong inside a loop or an if, and how the program is split into parts such as functions.

      
Block code shows structure with shapes: a C-shaped block wraps around the blocks inside it. Text code needs symbols instead. Python uses indentation (spaces at the start of a line). JavaScript and Java use curly braces { }.

      
In Python, indentation is part of the syntax. In JavaScript, indentation is only there to help people read, but every good programmer uses it.

      Lesson 5 · Complexity
      
Bigger tasks, bigger programs

      
CS1.K3CS1.K2

      
Complexity describes how many parts a program has and how they depend on each other. Text languages can handle very complex tasks, such as apps, games and operating systems, that would be hard to build from blocks.

      
Complex programs have many lines and many connected parts. A change in one place can break something in another place. Programmers manage complexity with clear structure: named functions, comments, and testing small parts one at a time.

      
The sizes in the model are rough orders of magnitude, not exact counts. Each step on the scale is ten times bigger.

      Lesson 6 · Pseudocode
      
Plan first, then code

      
CS1.K5CS1.S3

      
Pseudocode is a step-by-step description of an algorithm that looks like the structure of a programming language. It uses plain words, but it is laid out like code, with steps in order and indentation for the parts inside an IF or a loop.

      
Pseudocode is written for people, so a computer does not run it. There is no single official rule book. Many people write keywords such as IF, THEN and ELSE in capitals to make them stand out.

      
Because pseudocode does not depend on one language, a team can plan an algorithm first and then write it in Python, JavaScript or any other language.
